{% comment %} Shared workspace tree rail: the tree-collapse toggle, the tree pane itself, and the drag-resize separator. This partial exists so Home and note-detail can reuse the exact same markup rather than duplicating it, bounded to exactly the rail/tree/separator group, not the editor, not any page's own content column. Callers wrap this include in `.workspace-shell__layout` and supply `id_prefix` exactly as `_tree_nav.html` itself expects. The collapsed rail's purpose is narrowed to exactly one thing -- reveal or hide the note tree. The rail carries no Trash icon of its own: `_tree_nav.html` already has its own fixed Trash destination at the bottom of the expanded tree, which is the only Trash affordance this navigation surface offers, avoiding a second, redundant destination. The toggle itself is a compact double-chevron icon (rotated by CSS to point the opposite direction once expanded) plus dynamic `aria-label`/`data-tooltip` text -- "Show note tree" / "Hide note tree" -- kept in sync by `tree-shell.ts`'s existing `render()` method, which updates `aria-expanded`/`aria-label` on every collapse/expand and also drives `data-tooltip` the same way. `TreeShellController` only applies the persisted collapsed state to `[data-tree-shell]` once `app.js` runs -- a `defer`red module script, which executes after the browser may already have painted this section in its server-rendered default (expanded) state. This is a latent gap whenever a real full-page navigation happens *from* a collapsed tree while the user is looking directly at this area -- every other collapsed-tree action either stays client-side or (like the tree's own controls) is itself inside the now-hidden pane. New folder, reachable from the active-note overflow even while the tree is collapsed, is the one path that triggers it: creating a folder navigates back to this same page, and the tree would flash open (server default) before immediately snapping collapsed again once `app.js` caught up. The synchronous, non-deferred script below -- mirroring `base.html`'s own theme anti-flash bootstrap -- applies `data-tree-collapsed` before first paint instead, so `TreeShellController`'s later, unchanged `render()` call finds the state already correct and never visibly changes it. {% endcomment %}
