For Administrators

This section covers administrator actions available inside RidgeNote itself.

Server setup, Docker, SMTP, database maintenance, reverse proxy configuration, backups of the RidgeNote server, and other deployment tasks are outside the scope of in-app Help and should be handled through the operator documentation. This also covers emergency administrator password recovery for an administrator who cannot sign in and has no other administrator available to help.

Managing users

Open Admin from the account menu to reach the Users list.

From there, administrators can create new users, manage invitations, and open an individual user's account for additional actions.

Creating and inviting users

When creating a user, you can either set an initial password directly or create an invitation that allows the user to choose their own password.

If email delivery is configured, RidgeNote can send the invitation automatically. Otherwise, the invitation link can be provided to the user manually.

Pending invitations can be:

  • Reissued, which creates a fresh invitation link.
  • Revoked when the invitation is no longer needed.

Managing an existing account

Open a user from the Users list to manage that account.

Depending on the account's current state, administrators can:

  • Change the user's role.
  • Disable or re-enable the account using Enabled.
  • Reset the user's password on their behalf.
  • Schedule deletion.
  • Cancel deletion while the account is still within its recovery period.
  • Permanently purge an account once it becomes eligible.

Account deletion and recovery

Selecting Schedule deletion immediately disables the account and begins a 7-day grace period.

During those seven days, Cancel deletion can be used to keep the account and return it to service.

After the recovery period expires, Permanently purge becomes available. Purging requires typing the account's exact username as confirmation and cannot be undone through RidgeNote.

Permanent purge removes the account and its RidgeNote library, including its notes, folders, and tags.

Administrator safety protections

RidgeNote includes protections intended to prevent an administrator from accidentally removing the last usable administrator account.

In particular:

  • The last active administrator cannot be disabled or scheduled for deletion.
  • An administrator cannot permanently purge their own account.

These protections help ensure that RidgeNote always retains an account capable of performing administrative tasks.

Administrator Recovery

Open Global Trash Recovery from the account menu to view recoverable notes and folders belonging to RidgeNote users.

Items appear here after they leave the owner's own Trash window but before they reach the final 90-day purge boundary. See Trash and Recovery for the full lifecycle.

Administrators can identify recoverable items using limited metadata, but Administrator Recovery does not provide access to the contents of a deleted note.

Where recovered notes go

When possible, RidgeNote restores a note to its original folder.

If the original folder is no longer available, RidgeNote places the note in the user's Recovered Items folder instead.

If an unrelated folder already uses that name, RidgeNote automatically chooses a safe alternative name such as Recovered Items (2) rather than overwriting, renaming, or merging the existing folder.

Recovering folders when a name is already in use

Administrator folder recovery is designed to avoid overwriting an active folder.

If a recovered folder's original name is already being used, RidgeNote automatically restores the folder under a safe alternative name such as:

  • PROJECTS (Restored)
  • PROJECTS (Restored 2)

RidgeNote does not merge the recovered folder into the existing one or overwrite either folder.

Associated notes that are still eligible for recovery are restored with the folder.

Administrator Recovery is not a backup

Administrator Recovery exists to help users recover recently deleted information. It is still subject to RidgeNote's recovery time limits and final purge process.

It should not be treated as a substitute for regular Library Backups or whole-system backups maintained by the RidgeNote operator.

See Library Backup and Restore for the user-level backup and restore tools.
